# Git & GitHub 학습 정리

## 1. Git / GitHub
- **Git & GitHub를 사용해야 하는 이유:** 코드의 변경 이력을 체계적으로 관리하고, 여러 개발자와 안전하게 협업하기 위해서입니다[cite: 4].
- **Git과 GitHub의 차이:** Git은 내 컴퓨터에서 코드를 관리하는 버전 관리 시스템이며, GitHub는 Git으로 관리한 코드를 클라우드에 저장하고 공유하는 플랫폼입니다[cite: 4].
- **Repository:** 소스 코드와 파일들이 저장되어 관리되는 공간(저장소)을 의미합니다[cite: 4].
- **Commit:** 파일의 변경 사항을 로컬 저장소에 기록(저장)하는 작업입니다[cite: 4].
- **Branch:** 기존 코드를 유지한 채 독립적으로 새로운 기능을 개발할 수 있도록 나누는 분기 공간입니다[cite: 4].

## 2. git 기본 명령어
- **git config:** Git을 사용할 때 필요한 사용자 이름, 이메일 등의 기본 환경 설정을 지정하는 명령어입니다[cite: 4].
- **git init:** 현재 로컬 폴더에 새로운 Git 저장소를 생성하는 명령어입니다[cite: 4].
- **git status:** 현재 작업 중인 폴더의 변경 상태(수정된 파일, 스테이징 상태 등)를 확인하는 명령어입니다[cite: 4].
- **git add:** 변경된 파일을 다음 커밋 대상(Staging Area)으로 올리는 명령어입니다[cite: 4].
- **git commit:** 스테이징된 파일들의 변경 이력을 로컬 저장소에 최종 기록하는 명령어입니다[cite: 4].
- **git push:** 로컬 저장소에 기록된 변경 이력을 원격 깃허브(GitHub) 저장소로 업로드하는 명령어입니다[cite: 4].
- **git pull:** 원격 깃허브 저장소의 최신 변경 내용을 로컬 저장소로 받아와 동기화하는 명령어입니다[cite: 4].

## 3. Branch
- **git branch 명령어:** 현재 생성된 브랜치 목록을 확인하거나 새로운 브랜치를 생성·삭제하는 명령어입니다[cite: 4].
- **브랜치 관리(main, develop, feature, hotfix, release):** 목적에 따라 메인, 개발, 기능 추가, 긴급 수정 등의 역할을 나누어 체계적으로 브랜치를 운영하는 전략입니다[cite: 4].
- **Fast-forward:** 브랜치 분기 이후 메인 브랜치의 변화가 없을 때, 단순히 포인터를 최신 커밋으로 빠르게 이동시키는 합치기 방식입니다[cite: 4].
- **3-way merge:** 두 브랜치가 각각 새로운 커밋을 가졌을 때, 공통 조상과 양쪽의 변경 사항을 비교하여 새로운 병합 커밋을 만드는 방식입니다[cite: 4].
- **Merge conflict:** 동일한 파일의 같은 부분을 동시에 수정하여 Git이 자동으로 합치지 못하고 사용자의 수동 해결이 필요한 충돌 상황입니다[cite: 4].
